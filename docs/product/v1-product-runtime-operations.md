# v1 产品方向：模型配置、运行与运维

> 状态：Planned Product Direction
>
> 约束：遵循 [`../v1-architecture-plan.md`](../v1-architecture-plan.md) 的应用用例边界、Execution Profile 冻结、显式错误和持久化任务协议。

## 1. 产品目标

让用户能够安全配置模型、理解创作进度和费用、在本地或服务器持续运行，并在失败后知道发生了什么以及如何恢复。

## 2. 从 v0 保留什么

保留用户价值：首次配置引导、多 Provider/模型、角色模型选择、连接测试、TUI + Headless、Docker、流式活动、用量记录、诊断报告、安装与更新。

不迁移静默兜底模型、分散重试、配置热修改在途请求或只能靠读取内部文件排障的体验。

## 3. 配置体验

配置分为三层：

- Provider 账户（连接）：协议、Base URL、密钥和已保存的模型列表；密钥不进入 Project Authority 或日志；
- 默认绑定：当前连接、模型与思考强度；
- 角色映射：策划（architect）、作者（writer）、编辑（editor）各自可改用另一连接的模型与思考强度，未设置的角色跟随默认；独立语义分析用默认绑定。

首次运行有配置引导，选模型前向服务商列出这组密钥能用的模型（顺带验证密钥）。连接、模型与思考强度随时可换（见下文），切换只影响之后开始的任务尝试；每次尝试记录实际使用的模型与思考强度，历史始终能解释当时用的是谁。

不提供隐式 Provider 切换或伪成功。凭证缺失、能力不支持和连接失败都明确显示，用户决定修改配置或重试。

### 模型设置（2026-10-19 重做，已实现）

默认配置位置是 `~/.ainovel/v1/config.json`，与启动工作目录无关。启动合并环境变量后没有模型配置，或配置解析、模型装配失败时进入模型设置；环境配置完整时不要求文件存在。页面沿用首页外框（顶栏「AINOVEL / 模型设置」，底栏嵌反馈的分隔线与按键），内容是居中的一栏，紧贴顶栏从上往下排；渲染与鼠标热区同一遍生成。

- **总览**（从首页「模型设置」进入，已有连接时）：「当前」一行一个使用者——默认（连接 / 模型与上下文窗口）、思考强度（该模型可选的档位摊成一行，←→ 或点选即生效）、Architect / Writer / Editor / Chief（「跟随默认」或单独指定的模型，右侧是它自己的思考强度）。默认与角色的行回车或点击即从已保存的模型里换一个，角色另有首项「跟随默认」清除覆盖；单独指定了模型的角色 ←→ 调它自己的思考强度（首档跟随默认）。「连接与模型」按连接分组：连接行写服务商或格式与主机名，回车或点击编辑；其下是已保存的模型（● 当前、○ 其他，带上下文窗口），回车或点击即换用；每组末尾「+ 添加模型」，最后是「+ 添加连接」。列表装不下时开窗，组间空行也算在内。Esc 回首页（启动时因配置出错进来的，修好后 Esc 进首页）；配置位置写在页末。
- **删除**：连接行或模型行按两次 `d` 删除（删连接连同它的模型），中间按别的键取消；默认或某个角色还在用的拒绝，并说明先换掉谁。
- **添加连接**走三步：选服务商 → 填连接 → 选模型。服务商列表是内置服务商与「中转 / 自定义」。连接表单只问需要的：内置服务商先问 API Key，地址留空即官方地址；中转先选格式（OpenAI / Claude / Gemini，左右键或点选）、填地址再填密钥；OpenAI 格式另有 Chat Completions / Responses；能自取名字的连接（OpenAI、Claude、Gemini 格式）最后问名称，按地址主域名自动起名（`api.wool.dev` → `wool`），重名加序号，用户改过就不再跟着地址变。焦点行下方一句说明。除 Ollama 与 OpenAI 格式的中转外，没填密钥不往下走。
- **选模型**：表单回车即向服务商列出这组凭据能用的模型（`litellm.ModelLister`），密钥被拒、地址不合法回到表单并定位到对应行；网络失败或中转不支持列模型时不拦路，改为直接输入模型 ID。列表按模型清单认识的对话模型在前、新发布的在前排列，带上下文窗口与每百万 token 标价；打字即筛选，输入的文字不是列表里的某个模型时末尾多一行「使用「…」」。回车或双击用上所选模型：连接与模型一起写入并设为默认，绑定成功才落盘；首次配置随即进首页，从首页来的回到总览。手动输入的模型 ID 先发一句极短的对话试用（请求与创作同形，只换消息，花很少的 token），试不通留在模型页并给出服务商原话——ID 拼错当场知道，不用等开写；列表里的模型不再试。已保存连接的「添加模型」借生效连接的凭据列出，已添加的打勾，选中即换用，不改写连接本身。
- **编辑连接**：带出配置文件里原有的格式、地址与密钥（名称不改；环境变量覆盖的值不带出，免得随保存写进文件），回车先列模型验证密钥，再只保存连接、不换默认模型；连不上时照样保存并说明没能验证。内置服务商的连接名就是服务商名，再次选同一服务商即带出已保存的连接接着改。
- 列模型与试用期间 Esc 取消，迟到结果丢弃；服务商报错里的密钥一律隐去。

### 连接身份与协议

自定义连接只选接口格式：界面显示「OpenAI 格式」「Claude 格式」「Gemini 格式」，配置保存为 `openai`、`anthropic`、`gemini`；支持左右键和鼠标，不接受自由文本，窄窗口里选项自动折行。官方接口与中转的差别不交给用户选，由装配按地址推出：OpenAI 格式的连接指向官方地址（留空或 `api.openai.com`）或走 `responses` 接口时按 OpenAI 官方接口对接，其余地址（中转、网关、自部署）按通用的 Chat Completions 对接——它们的思考放在 `reasoning_content` / `reasoning` 字段、输出上限用 `max_tokens`，官方实现都不认。只有 OpenAI 格式展示 `chat` / `responses` 选项。内置服务商保留自己的适配器标识；配置校验同样拒绝未知协议和将其他内置适配器作为自定义协议使用。

顶层 `provider` 引用 `providers` 中的连接名称，名称可以自定义。每个连接独立保存 `type`、`api_key`、`base_url` 和 `models`；`type` 决定底层协议，OpenAI 的 `api` 可选 `chat` 或 `responses`，接口形式参与执行配置摘要。

新建连接不能与已保存的连接重名，编辑连接只改它自己，其他连接保留。配置只有连接映射这一种形态，没有扁平旧格式的读取或迁移；通过同目录临时文件同步、原子替换并设定 `0600` 权限保存。

环境变量只覆盖当前连接；`AINOVEL_PROVIDER` 选择连接，`AINOVEL_PROVIDER_TYPE` 和 `AINOVEL_API` 覆盖协议和接口，`AINOVEL_THINKING` 覆盖默认思考强度，密钥与地址不会从另一连接继承。连接名在模型装配前解析，创作内核不依赖这些配置结构。

覆盖只在内存里：绑定服务同时持有配置文件那层与叠上环境变量后生效的那层，每次修改（模型设置、`/model`、Headless `model`）两层一起改，按生效那层绑定，只把文件那层落盘——环境变量里的密钥、模型不会因为界面上改了别的而写进 `config.json`。文件那层可以不完整（默认绑定全由环境变量给出时，只存思考强度、角色这些改动）；改动引用只由环境变量定义的连接时，文件那层没有它，照实报错。

### 随时切换连接、模型与思考强度（已实现）

模型绑定是运行时属性，不是任务身份的一部分：切换不重建应用、不断活动流，也不让排队的任务失效。

- 生效时机：切换立即保存到配置文件并重绑运行时；排队中的任务在下一次尝试直接用新绑定，正在执行的尝试用原来的模型跑完。要让当前任务立刻换模型：Esc 暂停再回车继续。
- 思考强度是意图：`auto`（沿用模型默认）、`off`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`。它保存在配置里、换模型不抹掉；执行时按该模型的能力解析成生效档位，模型不支持思考就按自动执行。角色的思考强度可设 `inherit` 跟随默认。
- 角色映射：`roles.writer / architect / editor` 各自记录连接、模型与思考强度；只指定模型时思考强度跟随默认。清除覆盖即跟随默认。
- 环境变量仍在下次启动时优先于文件：界面里切换当场生效、保存的是文件那层，启动时若设了 `AINOVEL_MODEL` 等变量，以变量为准。
- 首页「模型设置」：默认与各角色的模型、思考强度都在总览里分配（见上文）。
- 工作台：`/model [architect|writer|editor]` 打开内嵌面板（角色 / 连接 / 模型 / 思考强度），←→ 切选项、Tab 或 ↑↓ 换行、Enter 应用、Esc 取消；应用后底栏说明生效时机。底栏模型摘要在思考强度非自动时附「思考 高」，有角色覆盖时附「角色 N」。
- Headless：`model` 输出默认与各角色的当前绑定；`model list` 列出全部连接与已保存模型（带编号）；`model use [--role R] [--connection C] <模型|编号>` 切换；`model use --role R --inherit` 清除角色覆盖；`model effort [--role R] <档位|inherit>` 调思考强度。模型名可能自带 `/`，所以连接用 `--connection` 指定。
- 历史追溯：每次尝试的尝试摘要记下实际绑定（角色、provider、模型、生效思考强度、配置摘要）；语义合规检查用检查时刻的默认绑定，其模型记在对话记录里，用量并入所在尝试（D72）。

配置文件形态：

```jsonc
{
  "provider": "deepseek",
  "model": "deepseek-chat",
  "thinking": "high",
  "providers": {
    "deepseek": {"type": "deepseek", "api_key": "…", "models": ["deepseek-chat", "deepseek-reasoner"]},
    "proxy":    {"type": "openai", "api": "responses", "api_key": "…", "base_url": "…", "models": ["gpt-5"]}
  },
  "roles": {
    "writer":    {"provider": "proxy", "model": "gpt-5", "thinking": "medium"},
    "architect": {"provider": "deepseek", "model": "deepseek-reasoner"}
  }
}
```

## 4. 运行中心

运行中心以作品语言展示 CreationRun 和 Operation：

- 当前目标、章节进度、正在执行的动作和开始时间；
- 等待用户、暂停、失败、取消和完成；
- 最近事件、模型调用、工具调用和 Workspace 恢复点；
- 暂停、继续、取消、优先级和显式 restart；
- 单次任务与整本作品的 token、缓存、耗时和估算费用。

默认视图隐藏内部术语，诊断详情保留原始 ID、事件和错误链，满足普通用户与开发排障两类需求。

## 5. 诊断与隐私

具体设计、现有记录缺口、只读边界、分享白名单与实施验收见 [运行观测与问题诊断实施方案](v1-product-diagnostics.md)。首轮聚焦运行问题和用户反馈，内容质量体检后置。

诊断分为：

- 流程健康：停滞、重复失败、lease、等待原因和恢复位置；
- 内容健康：计划覆盖、摘要缺失、伏笔/角色状态异常和审阅趋势；
- 模型健康：调用错误、延迟、结构化输出、缓存和费用；
- 存储健康：迁移、Revision、Workspace、Derived 和备份状态。

提供可导出的脱敏诊断包：默认移除正文、Prompt、API Key 和用户私有素材，只保留行为骨架、版本、错误分类与必要统计。脱敏失败时拒绝导出，不用不完整规则冒险泄露内容。

## 6. 运行形态与交付

- TUI：面向本地交互创作；
- Headless：面向服务器、NAS、CI 和后台运行，结构化输出与事件流分离；
- 容器：配置、数据库和导出目录显式挂载；
- 安装/更新：发布包带校验，版本升级先验证数据库兼容性；
- 备份/恢复：以 SQLite Authority 和必要 Runtime 为明确边界，不复制临时 Derived 伪装成权威备份。

所有入口调用同一组应用用例，不为 Headless 或容器建立简化状态机。

## 7. 能力层次

### 基础运行

- 最小配置文件和首次引导；
- Provider/模型连接测试；
- CreationRun 进度、等待/失败原因和基础 usage；
- Headless 结构化输出及稳定退出码。

### 可观测增强

- 多 Provider、角色模型和推理强度；
- 缓存、费用、延迟和调用历史；
- 脱敏诊断导出；
- 后台恢复和运行通知。

### 长期运行

- Docker 与跨平台发布；
- 安全更新、数据库备份/恢复和兼容检查；
- 面向长期运行的日志轮转、Workspace 清理与 Derived 淘汰。

## 8. 验收标准

1. 新用户无需编辑源码即可配置并验证一个真实模型；
2. 同一 Operation 的模型、Prompt 和工具快照在运行中不被配置修改污染；
3. 用户能从界面判断任务在运行、等待、失败还是可恢复；
4. Token、缓存、耗时和费用可以按 Operation 与 CreationRun 追溯；
5. Headless 中断后重启不重复提交内容；
6. 诊断包不包含密钥、正文或完整 Prompt。
