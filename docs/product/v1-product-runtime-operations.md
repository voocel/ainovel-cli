# v1 产品方向：模型配置、运行与运维

> 状态：Planned Product Direction
>
> 约束：遵循 [`../v1-architecture-plan.md`](../v1-architecture-plan.md) 的 Service 边界、Execution Profile 冻结、显式错误和持久化任务协议。

## 1. 产品目标

让用户能够安全配置模型、理解创作进度和费用、在本地或服务器持续运行，并在失败后知道发生了什么以及如何恢复。

## 2. 从 v0 保留什么

保留用户价值：首次配置引导、多 Provider/模型、角色模型选择、连接测试、TUI + Headless、Docker、流式活动、用量记录、诊断报告、安装与更新。

不迁移静默兜底模型、分散重试、配置热修改在途请求或只能靠读取内部文件排障的体验。

## 3. 配置体验

配置分为三层：

- Provider 账户：协议、Base URL、密钥和连接能力；密钥不进入 Project Authority 或日志；
- 模型档案：模型名、上下文窗口、结构化输出能力、推理强度和价格信息；
- 角色映射：Writer、Planner、Editor 及独立语义分析使用哪个模型档案。

首次运行提供最小引导和真实连接测试。配置修改只影响新 Operation 或显式 restart；历史 Execution Profile 始终能够解释当时使用的模型与参数。

不提供隐式 Provider 切换或伪成功。凭证缺失、能力不支持和连接失败都明确显示，用户决定修改配置或重试。

## 4. 运行中心

运行中心以作品语言展示 CreationRun 和 Operation：

- 当前目标、章节进度、正在执行的动作和开始时间；
- 等待用户、暂停、失败、取消和完成；
- 最近事件、模型调用、工具调用和 Workspace 恢复点；
- 暂停、继续、取消、优先级和显式 restart；
- 单次任务与整本作品的 token、缓存、耗时和估算费用。

默认视图隐藏内部术语，诊断详情保留原始 ID、事件和错误链，满足普通用户与开发排障两类需求。

## 5. 诊断与隐私

诊断分为：

- 流程健康：停滞、重复失败、lease、等待原因和恢复位置；
- 内容健康：计划覆盖、摘要缺失、伏笔/角色状态异常和审阅趋势；
- 模型健康：调用错误、延迟、结构化输出、缓存和费用；
- 存储健康：迁移、Revision、Workspace、Derived 和备份状态。

提供可导出的脱敏诊断包：默认移除正文、Prompt、API Key 和用户私有素材，只保留行为骨架、版本、错误分类与必要统计。脱敏失败时拒绝导出，不用不完整规则冒险泄露内容。

## 6. 运行形态与交付

- TUI：面向本地交互创作；
- Headless：面向服务器、NAS、CI 和后台运行，结构化输出与事件流分离；
- 容器：配置、数据库和导出目录显式挂载；
- 安装/更新：发布包带校验，版本升级先验证数据库兼容性；
- 备份/恢复：以 SQLite Authority 和必要 Runtime 为明确边界，不复制临时 Derived 伪装成权威备份。

所有入口调用同一 Service，不为 Headless 或容器建立简化状态机。

## 7. 能力层次

### 基础运行

- 最小配置文件和首次引导；
- Provider/模型连接测试；
- CreationRun 进度、等待/失败原因和基础 usage；
- Headless 结构化输出及稳定退出码。

### 可观测增强

- 多 Provider、角色模型和推理强度；
- 缓存、费用、延迟和调用历史；
- 脱敏诊断导出；
- 后台恢复和运行通知。

### 长期运行

- Docker 与跨平台发布；
- 安全更新、数据库备份/恢复和兼容检查；
- 面向长期运行的日志轮转、Workspace 清理与 Derived 淘汰。

## 8. 验收标准

1. 新用户无需编辑源码即可配置并验证一个真实模型；
2. 同一 Operation 的模型、Prompt 和工具快照在运行中不被配置修改污染；
3. 用户能从界面判断任务在运行、等待、失败还是可恢复；
4. Token、缓存、耗时和费用可以按 Operation 与 CreationRun 追溯；
5. Headless 中断后重启不重复提交内容；
6. 诊断包不包含密钥、正文或完整 Prompt。
