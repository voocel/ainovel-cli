# v1 产品设计：创作控制台

> 状态：已实施。现行布局采用三栏与中栏上下分区。
>
> 约束：遵循 [架构基线](../v1-architecture-plan.md) 与 [创作工作台总纲](v1-product-creation-workbench.md)。页面只拥有展示和交互状态，不建立新的创作模式或业务状态机。

## 1. 设计目标

用户能同时观察工作过程、阅读作品、检查约束，并随时提出要求。界面明确回答：

- 正在执行什么，进展到哪里，为什么等待；
- 模型正在思考、说明或生成什么；
- 哪些内容只是预览，哪些等待批准，哪些已经入稿；
- 用户的输入作用于谁，何时生效。

借鉴已有产品的三栏空间分工与独立事件／输出视口，不引入旧版的执行协议、领域状态或代码依赖。

## 2. 空间与视觉

```text
作品与运行状态                                            已入稿进度
模型与用量                                                导航提示
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
概览与目录          │ 执行事件                            │ 创作控制
                    │ 时间 / 动作 / 结果 / 耗时            │ 待办
                    ├────────────────────────────────────┤
                    │ F1 实时输出   F2 正文   F3 审阅      │ 本章上下文
                    │                                    │ 要求、规划
                    │ 思考 / 说明 / 正文预览               │ 事实、发现
                    │ 或：选中章正文 / 待确认方案           │
                    │                                    │
────────────────────────────────────────────────────────────────
› 输入创作要求或命令                              输入作用范围 / 审阅对象
──────────────────── 反馈（有消息时） ────────────────────────────
主要操作 · / 命令 · Tab 面板 · ↑↓ 滚动 · Enter 发送          模型名称
```

- 保留终端原生背景；墨绿强调当前焦点和操作，琥珀色标记待办，红色标记错误。状态同时使用文字与符号，不单靠颜色。
- 顶栏三行：作品状态、本轮用量、兼作进度条的分隔线。用量明确显示输入／输出 token、缓存命中 token 与占输入的比例，以及已知费用；无输入用量时命中比例显示「—」。底栏五行：上分隔线、输入与右侧作用对象、下分隔线、左侧快捷提示与右侧模型名称、底部留白。反馈嵌入下分隔线，出现时不改变布局高度。
- 最小窗口 150×40，更小只显示最大化提示，返回与退出仍有效。
- 左右栏各 32 列；180 列起分别为 34 和 36 列；其余宽度属于中栏。
- 中栏上方为执行事件，默认占主体高度 25%，至少六行；`/split 20–50` 显式调整占比，本次打开期间有效。
- 中栏下方是固定标签行与内容区。正文行宽不超过 96 个终端单元；中文标点及组合字符沿用 Unicode 断行。
- 几何由 `benchLayout` 统一计算；事件、内容、目录和标签的渲染与鼠标命中共用坐标。输入、反馈及待办到达不改变区域位置。

## 3. 三个内容视图

### 实时输出（默认）

按任务、模型调用轮次和内容类型组织输出块。标题显示时间、任务名称与类型；类型使用明确文字：

- **思考**：仅展示服务提供的思考原文，多行呈现，可滚动阅读；不将其当作可靠解释。
- **说明**：模型的说明性文本，不能当作小说正文或提交结果。
- **正文预览**：从正文工具参数增量中提取的正文，明确标记「未入稿，最终以确认稿为准」。原始参数 JSON 不进入正文预览。

默认跟随最新输出。向上滚动冻结所读快照，之后的增量、任务切换、缓冲淘汰均不会改变所读内容。切换标签后再回来保留冻结位置；向下到冻结内容末尾或 `/follow` 恢复最新输出。

### 正文

点击章节进入正文视图，固定选中章；新任务和新稿件不抢走阅读位置。同章有候选稿时优先展示候选并明确标记，否则展示已入稿版本。纯流式内容只出现在实时输出中。

### 审阅

`F3`、`/review` 或点击右侧待办进入。对象是当前待裁决方案，与目录选中章节独立。展示候选章节、大纲及附带变更；过期稿件明确标记，只能提出意见重写。暂时没有稿件时展示空态。

输入 `y` 回车批准；文字回车作为当前候选的修改意见。没有进入审阅上下文时，`y` 只引导进入审阅，不提交决定。空回车只阅读或折叠，不批准。

三个标签只是查询／展示视图，使用同一个 Project、CreationRun 与审批用例。

## 4. 输入与导航

- 实时输出／正文视图里的普通文字始终是创作要求，即使存在待确认稿件；审阅视图里的普通文字是当前候选的修改意见。
- 第一次输入时固定章、卷弧、后续章节范围或审阅对象；随后切章、切标签不改变草稿的语义。清空或提交后释放。
- 若所绑定候选已替换或失效，保留文字并明确提示，不能把旧稿反馈用于新稿。
- `/note 内容` 在任何视图独立提出创作要求。要求提交后明确说明后续对应任务会采用，现有正文尚未改变。
- `F1/F2/F3` 或点击标签切换内容。`Tab` 按目录 → 事件 → 内容循环焦点；箭头和翻页键滚动焦点区。尚未形成目录时仍可翻阅输出。
- 点击目录选章或折叠卷弧；点击中栏可切换滚动焦点。输入框下方操作点击后填入命令，回车执行；不会覆盖未提交输入。
- `Esc` 依次清空输入、关闭全屏或返回直播、返回作品首页。离开只取消 UI 订阅，不取消创作。
- 命令支持唯一前缀；歧义时列出候选并保留输入。`/body` 与 `/budget`、`/note` 与 `/next`、`/stream` 与 `/stop` 与 `/split` 不能用有歧义的单字母代替。
- `/think` 全屏查看当前保留的思考块；`/view` 查看完整要求、规划、事实与发现；`/diag` 查看持久化诊断。

暂停只阻止后续推进，正在执行的任务可能继续收尾。终端原生划选复制通常需要按住 Shift。

## 5. 权威与实时数据

### 查询模型

`app/workbench.Reader` 提供作品、目录、候选、待办、有效发现、要求与事实等查询投影。作品权威数据绑定同一 Revision；运行与审阅证据每次刷新查询。TUI 不直接访问 Store。

正文校正链保持：

```text
实时预览（易失） → 工作稿候选（待确认） → 正式入稿（权威版本）
```

工具完成或模型声称完成都不等于正式入稿。入稿状态只能来自权威查询；候选保留 Operation 与 Base Revision，过期候选不能伪装成当前稿。

### 事件和输出块

`capability.Runtime` 将 agent 增量分类后交给 `infra/activity.Hub`。Hub 维护最新快照并通过容量为一的 channel 合并唤醒，不等待 UI 消费，不向数据库写流式 delta。

- 生命周期条目按调用 ID 配对，保留最近 64 条；显示时间、状态、已接收数据量、耗时和错误原因。
- `OutputBlock` 携带稳定 ID、版本、任务／调用归属、任务名称、类型、时间、文本和截断标记。
- 相邻思考／说明增量在同轮内合并；不同任务、不同轮次分开。交错的正文工具调用按调用 ID 独立累计。
- 输出最多保留 48 块、总文本 256 KiB；单块超过 40 KiB 时裁回约 32 KiB，裁剪保证 UTF-8 完整。淘汰和截断明确显示，不能被误解为完整会话历史。
- 换任务保留已收集的输出块，换 Run 清零；退出进程不恢复易失流。完整正文和待确认方案通过正式查询恢复。
- 快照复制输出内容，发布后不会修改读者已取得的快照。UI 按块 ID／版本缓存排版，冻结阅读持有所读快照。
- 所有事件保留 project/run/operation 归属，TUI 使用打开代际号隔离异步结果，跨作品切换不串台。

不额外采集未提供的思考，不把模型说明当正文，也不把展示缓冲当作品来源。

## 6. 右栏与长篇

任务状态区展示真实能力执行实例，优先显示运行中、未完成任务，再显示最近完成项，最多三项。每项显示任务名、当前阶段、耗时和重开次数；不预设虚构的 Agent 或等待队列。点击正常任务定位其保留输出并暂停跟随，底栏显示该任务输入／输出／缓存用量，`/follow` 恢复全局直播；点击异常任务展开具体原因。没有保留文本时明确提示。

任务开始和结束来自 Runtime.Execute 的实际生命周期，工具失败不直接等同整项任务失败；只有执行返回错误才标记未完成。状态和用量保存在进程内快照中，保留最近 32 项（运行中的任务不淘汰），换 Run 清零，不冒充可持久恢复的历史。

右栏聚合确认方式、修订预算与待办，下方按阶段呈现创作依据：

- 写作与阅读：选中章的有效审阅发现、生效要求（标注全书／章节等作用范围）、本章目标及事实。生效表示作用域匹配，不代表已通过逐项核验。
- 审阅：上下文跟随候选稿而非目录选中章，优先展示候选标识、新稿字数或相对已入稿正文的字数变化、标题调整、附带变更数及提交说明。多章／非章节方案显示整体变更，不混入某个目录章节的要求。
- 候选基线过期与读取异常明确提示。未提供的修订次数、上次退回原因和语义差异不推测。

各节长文本限制行数并标记未展开内容；章节全文详情可用 `/view`，候选稿及完整变更信息在 F3 审阅中查看。常用操作集中在输入框下方，右栏空间全部用于状态和上下文。

目录只绘制可见条目，未规划章节合并为区间；搜索可以展开必要祖先。折叠偏好按作品保存。查询合并保证单工作台最多一个快照读取在途。

Reader 在 Revision 不变时复用作品快照；首次打开及版本变化仍读取完整作品，尚未实现存储层正文按需加载。流式排版按块缓存，历史保留有界。

## 7. 验证

回归覆盖：

- 多尺寸、深浅主题、分区比例、标签命中与固定输入区；
- 思考／说明／正文隔离、轮次／任务边界、交错调用、快照隔离、输出容量与 UTF-8 截断；
- 输入期间切章、候选到达、审阅对象固定、普通要求不拒绝待审稿；
- 事件与输出独立滚动、冻结后新任务到达、切视图再返回、无目录时翻页；
- 候选优先、过期稿审批保护、长篇目录与排版、订阅取消和代际隔离。

使用 `BenchmarkLongWorkbench` 与 `BenchmarkLongWorkbenchStreaming` 观察界面排版成本；基准及示例帧不等价于真实模型端到端验收。
