# v1 产品设计：创作工作台页面

> 状态：Planned Product Design
>
> 约束：遵循 [`../v1-architecture-plan.md`](../v1-architecture-plan.md) 与
> [`v1-product-creation-workbench.md`](v1-product-creation-workbench.md)（工作台总纲）。
> 本文细化总纲 §5 五视图的页面布局、实时活动体验与流式数据管道（Service 用例层），
> 不定义新的创作内核语义。

## 1. 设计目标

工作台是用户全程停留时间最长的界面，页面设计围绕两个体验承诺：

1. **创作时永远看得到进展**——正在做什么（构思、落笔、审阅、自纠）、写到第几章，
   持续可见；不存在"黑盒等待"，用户的耐心由持续可见的进展供养，而不是由进度条许诺。
2. **空闲时一眼看清全局**——写到第几章、哪章待确认、下一步是什么，
   不需要任何操作就能回答"这本书现在怎么样了"。

一切文案使用创作语言（构思、落笔、审阅、确认），不出现 Operation、Proposal
等协议词（总纲 §5 既有约束）。

## 2. 页面布局

三栏 + 底部常驻区，按终端宽度自适应：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：书名 · N/M 章 · 状态徽章                                  │
├────────────┬───────────────────────────────┬─────────────────┤
│ 左栏·大纲   │ 中栏·主区                      │ 右栏·详情        │
│            │                               │                 │
│ 卷一 余信   │ 【创作中】                     │ 选中章的：       │
│ ● 1 山野少年│   活动流（事件行，带 spinner）  │ · 已确认事实      │
│ ◐ 2 深山奇遇│   ─────────────────           │ · 审阅发现       │
│ ▸ 3 玉简之秘│   正文预览区（见 §3）           │ · 意图与锁定摘要  │
│ ○ 4 ……    │                               │                 │
│ ○ 5 ……    │ 【待决定】决定卡置顶            │                 │
│            │ 【空闲】选中章正文阅读          │                 │
├────────────┴───────────────────────────────┴─────────────────┤
│ 决定卡 / 输入框（常驻）+ 快捷键提示                              │
└──────────────────────────────────────────────────────────────┘
```

### 左栏·大纲

- 蓝图树按 卷 → 弧 → 章 呈现（数据即 Plan 节点树，parent/order 已有）；
- 章节状态徽标：`●` 已确认（正文已入权威库）、`◐` 待确认（候选稿等你验收）、
  `▸` 进行中（写作/重写/审阅中细分文案）、`○` 已规划、
  灰色占位 = 目标内尚未规划（滚动窗口外）；
- ↑/↓ 选章、回车在主区阅读该章；
- 长书通过视口滚动呈现（窗口随选中行移动，截断处有方向指示），
  不按固定章节数切换布局；
- 卷/弧头行回车（或点击）折叠/展开：折叠头行给出章数摘要，子树含待确认章
  时追加 ◐ 提示；折叠偏好按作品记进用户级 state.json，跨启动记忆（M3）。

### 中栏·主区（三态）

- **创作中**：上部为活动流（见 §3），下部为正文预览区；新内容自动滚动跟随，
  用户上滚即停止跟随、回到底部恢复（v0 `convFollow` 经验）；
- **待决定**：决定卡置顶（总纲 §5：决定卡是第一交互），下方展示相关上下文
  （待确认候选稿、审阅发现）；`y` 明确通过，`n` 后输入意见并回车要求重写；
  空回车不提交，但必须给出一行指引（"按 y 确认通过，或输入修改意见"），不得无响应；
- **空闲/完成**：显示左栏选中章的正文，无选择时显示总览与下一步引导。

默认跟随当前运行状态；用户手动选章、滚动或切换视图后固定当前内容，只在顶栏和
底部提示创作进度或待决定事项，不抢走阅读焦点。回到活动流后恢复自动跟随。

### 右栏·详情（≥140 列才显示）

选中章的已确认事实（按五类分组）、该章审阅发现、创作意图三要素与用户锁定范围摘要。
右栏是只读投影，编辑入口留给"精细控制"层（总纲 §8），本设计只预留位置不实现编辑。

### 宽度自适应降级

- `< 140` 列：收起右栏（详情并入主区按键展开）；
- `< 100` 列：收起左栏（大纲变为主区的一个视图，Tab 轮换）——即现状单栏形态；
  降级只减少并排呈现，不减少能力。

## 3. 实时活动（核心体验）

### 正文的真实流向（设计前提）

v1 的章节正文不是模型的对话文本：Writer 通过 `workspace_put_chapter` 的**工具参数**
提交整章 JSON。因此在 agent 事件流里：

- 说明性文字 delta（`DeltaText`）只是模型的过渡叙述，**不是正文**；
- 真正的正文以 JSON 参数增量（`DeltaToolCall`）形式流出。

任何把 `DeltaText` 当正文渲染的方案都会让用户看到碎碎念而错过真正的章节文字。
据此，实时体验分两步交付：

### 事件级活动流（先行，M2）

一行一事件，来源于 agent 生命周期（工具调用起止、提交、重试、审阅裁定）：

```text
✓ 查阅设定与前情              （authority_read 完成）
⠋ 正在落笔章节工作稿……        （workspace_put_chapter 进行中，spinner + 已接收数据）
```

- 工具名到创作语言有唯一翻译表（authority_read=查阅设定与前情、
  workspace_put_chapter=落笔章节工作稿、workspace_replace_block=修改段落、
  workspace_put_candidate=整理结构候选、workspace_put_review=记录审阅意见、
  proposal_submit=提交候选稿、verdict_submit=给出审阅结论）；
- `DeltaToolCall` 在活动流中只显示已接收数据量，不冒充"正文字数"（JSON 字段、
  转义符和其他参数不属于正文，真实字数在候选稿形成后统计）；正文预览由
  流式提取协议另行承载（见下）；
- 工具报错显示为一行警示 + 随行原因摘要（创作语言；原始诊断按 `d` 下钻：
  各任务错误、失败任务的事件记录、以及从已持久化消息提取的自纠工具报错——
  成功任务曾经的报错也可见；超长条目截断，完整内容始终在库里），与重试事件
  一起让"模型在自纠"可见而不是可怕；
- 模型的说明性文字（`DeltaText`）折叠为活动流中的辅助行，不进正文预览区；
- 思考（`DeltaThinking`）显示"构思中"状态行；Provider 提供思考文本（其明确
  标记的推理通道）时在状态行尾部附**原样截取的思考片段**（不是摘要——不做
  任何概括加工）。原始思考不同 Provider 未必提供、也不等于可靠解释，
  **不作为产品承诺与验收条件**。

### 正文逐字预览（M3 已实施：工具参数流式提取协议）

正文预览区的文字来自**工具参数流式提取协议**：从 `workspace_put_chapter` 的
部分 JSON 参数流中增量抽取 `chapter.blocks[].text`（`workspace_replace_block`
取顶层 `text`），单遍词法状态机 + 路径匹配，O(增量) 无回扫。协议要点：

- 任意字节切分安全：转义序列、`\uXXXX`、代理对、UTF-8 多字节跨片段都正确
  重组，每次产出的增量保证是合法 UTF-8（切分等价性有全切分点测试与 fuzz 守护）；
- 容错语义是**失败即停止发射、不做恢复式猜测**：预览是易失通道，猜错会把
  JSON 结构喷进预览，比预览停在半途更糟；权威正文始终以候选稿为准。停止
  发射不静默：中断时活动流出现一次性警示"正文直播中断（仅预览受影响）"，
  用户能区分"预览断了"与"模型停写了"；
- 每次工具调用一个独立提取器实例（按调用 ID 隔离）：重试或二次落笔零残留，
  并行调用交错（A→B→A）互不污染；状态生命周期以一条 assistant 消息为界
  （消息结束即清空，参数流不跨消息），无任意容量上限；
- 快照侧正文缓冲有界（尾部保留，约一整章有裕量），块间以空行分段；
- 预览区标注"逐字直播，最终以确认稿为准"（三层校正链不变）。

### 一致性原则（三层校正链）

流式内容是**通道不是来源**。正文的呈现层级与校正链：

```text
流式预览（易失，仅 UI） → Workspace 候选稿（待确认） → 用户批准 → Authority 正文
```

- operation 结束但等待批准时，authority 里还没有新章：页面以 **Workspace 候选稿**
  校正预览区并标记"待确认"（大纲徽标 `◐`）；
- 批准后切换为 Authority 版本（徽标 `●`）；
- TUI 中途退出或重进不回放历史 delta，直接从候选稿/权威快照续起。

## 4. 数据契约（Service 用例设计）

### WorkbenchSnapshot：统一只读查询模型（M1）

现有 Project 快照不含章节级运行状态、待确认候选与有效审阅发现，
TUI 目前靠多个调用自行拼接。M1 新增一个只读查询用例，TUI 与未来 Web/桌面端
复用同一模型（落实总纲 §8），入口层不得自行拼 Store 数据：

```text
WorkbenchSnapshot
├─ project_revision            当前权威 Revision
├─ outline                     蓝图树 + 每章状态（已确认/待确认/进行中/已规划/未规划）
├─ active_run                  最近一轮创作（含终态）+ 当前进行中的环节
├─ selected_chapter            选中章正文（权威版；候选稿附 operation/base_revision）
├─ pending_decision            待决定事项（决定卡数据源）
├─ valid_review_findings       绑定当前 Revision 的审阅发现
└─ next_step                   下一步引导（创作语言）
```

快照中所有权威投影必须绑定同一个 `project_revision`；候选稿必须保留 Operation 与
Base Revision，过期候选不得伪装成当前稿件。

### 活动管道（M2）

实时通道与权威存储分离，不改变任何持久化语义：

```text
agentcore Agent（循环流式执行，Subscribe 提供生命周期事件与 delta）
   │  Event{message_update Delta/DeltaKind, tool_exec_start/end, retry, …}
   ▼
capability.Runtime.Execute —— 可选 ActivitySink 注入（nil 则零开销）
   ▼
ActivityHub —— 进程内最新活动快照（非持久化）
   ▼
service —— SubscribeRunActivity(projectID) 订阅活动变化
   ▼
TUI 工作台（bubbletea 消息泵）
```

ActivityHub 属于 Runtime Plane，由组合根注入；`capability` 与 `service` 只依赖其接口，
`capability` 不得反向依赖 `service`。

**交付契约（必须全部满足）**：

1. **发布非阻塞**：agentcore 的订阅监听器是同步执行的。ActivitySink 只更新
   ActivityHub：生命周期写入活动快照，连续 delta 合并为最新进度；订阅 channel 仅发送
   容量为 1 的唤醒信号，信号可以合并。发布不直接向 UI 投递事件，UI 卡顿不得拖慢创作。
2. **取消语义**：SubscribeRunActivity 返回取消函数；离开页面/切书只取消订阅，
   **绝不取消创作**；订阅者退出后发布端无泄漏。
3. **顺序与合并**：ActivityHub 按 operation 保留有序生命周期和最新 delta 进度；
   TUI 被唤醒后读取完整活动快照，不依赖收到每个通知。
   约定的工程边界：快照保留最近 64 条生命周期条目（超出丢最旧，收尾事实通过
   补条目保证不丢）、说明性文字辅助行只留尾部 120 字、错误摘要截断 200 字；
   delta 本就合并为进度，不产生缓冲。
4. **身份校验**：每条活动事件携带 project/run/operation 归属（发布侧标注为
   本设计新增）；TUI 消费侧沿用既有 `bench.gen` 代际号校验（已有测试守护），
   跨作品切换不串台。
5. **持久化不变**：operation_events 照旧只记消息级提交；流式 delta 不落库、
   不参与恢复语义；headless 不受影响。

## 5. 键位

| 键 | 语义 |
|---|---|
| Tab | 栏间焦点轮换（大纲 → 主区 → 详情） |
| ↑/↓ | 栏内移动（大纲选章 / 主区滚动） |
| 回车 | 大纲：章行阅读选中章、卷/弧头行折叠/展开；修改意见输入框：提交重写意见 |
| Esc | 分层返回：先关展开面板 → 再回欢迎页 |
| y / n | 明确通过 / 输入修改意见 |
| c / g / b | 继续创作 / 调整目标章数 / 调整自动修订预算 |
| p / x / d | 暂停 / 取消 / 查看诊断（含各任务错误与失败任务的事件下钻） |

鼠标（M3，用户裁决滚轮+点击）：滚轮 = 指针所在栏的 ↑/↓ 语义；点击章行选中、
点击卷/弧头行折叠、点击栏切焦点、单栏点击标签切视图；全屏阅读态滚轮翻页。
代价（已知取舍）：开启鼠标捕获后终端原生划选复制需按住 Shift；键盘始终覆盖
全部操作。

## 6. 交付分期

- **M1 骨架**：WorkbenchSnapshot 查询用例 + 三栏布局 + 大纲树（含 `◐` 待确认态）+
  详情栏 + 明确审批键位 + 宽度降级。快照轮询驱动，不引入活动管道。
  单独可交付：空闲与待决定态体验即完整。
- **M2 实时活动**：ActivitySink 管道贯通（含 §4 交付契约全部五条）+ 事件级活动流 +
  落笔活动状态 + 跟随滚动。创作态"永远看得到进展"达成。
- **M3 正文逐字预览与打磨（已交付）**：工具参数流式提取协议（§3，设计经评审
  后实施，中断显式警示）、大纲卷/弧折叠、思考片段展示（Provider 标记的思考
  文本原样截尾进构思行，非摘要）、错误事件随行原因 + `d` 诊断下钻
  operation_events 与自纠工具报错、鼠标热区（滚轮+点击，划选复制取舍见 §5）、
  布局偏好记忆（折叠状态跨启动，保存失败有提示）。

## 7. 验收标准

1. 创作全程主区始终有可见进展：任一时刻用户能说出"现在在写第几章、在做什么"
   （事件级活动流即须达成，不依赖逐字正文流）；
2. 正文呈现遵循三层校正链：待确认候选稿明确标记，批准后以权威版本替换；
   流式预览与最终权威正文不一致时以权威为准；
3. 大纲状态与权威快照一致；选中章节后一次回车即可阅读正文；批准必须由 `y` 明确确认，
   空回车不得提交 Authority，且必须回以确认指引而非无响应；
4. 全部用户可见文案为创作语言，不出现协议词；
5. 宽度降级只减并排呈现，不减能力；窄终端仍可完成全部操作；
6. 活动发布不反压模型执行：UI 消费停滞时创作速度不受影响（可测：阻塞订阅者，
   对比 operation 耗时）；
7. entry 不碰 store（架构测试）；headless 行为与性能不受活动管道影响；
8. 活动事件带作品归属，消费侧代际号校验，跨作品切换不串台。
