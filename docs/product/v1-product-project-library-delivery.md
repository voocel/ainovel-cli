# v1 产品方向：作品库、导入与交付

> 状态：Planned Product Direction
>
> 约束：遵循 [`../v1-architecture-plan.md`](../v1-architecture-plan.md) 的 Project Authority、Revision、显式投影和只读导出边界。

## 1. 产品目标

让用户能够创建、找到、继续、备份和交付自己的作品。数据库和内部协议服务可靠性，用户最终面对的是作品、章节和成品文件。

## 2. 从 v0 保留什么

保留用户价值：多本作品管理、从一句话或大纲文件开始、导入外部小说续写、接纳手工修订、随时导出 TXT/EPUB，以及中断后继续导入。

不迁移“一本书绑定一个工作目录”的事实模型，也不直接读取 v0 `output/`。v0 数据迁移仍按核心 D12 明确不做；外部 TXT/Markdown 小说是新的通用导入能力，不是 v0 兼容层。

## 3. 作品库

作品库展示：书名、简介、当前 Revision、章节数、CreationRun 状态、最近活动和成品导出时间。用户可以创建、打开、归档和删除项目；删除必须有明确范围和可恢复策略。

创建作品提供三个入口：

1. 一句话创建；
2. 详细表单或大纲文件创建；
3. 导入已有小说并选择继续创作或只管理成品。

三个入口只产生不同初始化输入，不创建不同 Project 类型。

## 4. 外部编辑与导入

现有 JSONC Project Projection 继续作为完整、可审计的高级编辑入口。产品层可以增加更友好的 Markdown 章节投影，但必须携带 `base_revision`，导入时生成用户修改并明确处理冲突，禁止后台文件监听自动覆盖 Authority。

导入已有小说采用持久化分阶段任务：源文件快照、章节识别、用户确认、逐章事实提取、全书综合和原子发布。中间结果留在所属 Workspace，失败不产生“半本正式作品”，恢复按输入 digest 继续，不依赖用户记住进度。

第一阶段只支持 TXT/Markdown 和明确编码；模型负责开放语义，代码负责字节覆盖、顺序、类型、幂等与发布。

## 5. 成品导出

导出是指定 Project Revision 上的只读投影，不创建 ChangeSet，也不影响正在运行的创作。

- TXT：书名、卷分隔、标准章节标题和正文；
- EPUB：元数据、目录、卷章结构和稳定作品标识；
- 范围导出：允许选择章节区间，明确报告尚未完成或缺失章节；
- 覆盖策略：默认不覆盖已有文件，用户显式选择后才覆盖；
- 内容边界：Intent、Canon、审阅记录和内部 ID 不进入读者成品。

同一 Revision 和相同导出选项应产生稳定内容；导出器只读取 Service 提供的作品投影，不直接理解运行状态机。

## 6. 能力层次

### 基础查看与导出

- 作品列表、作品详情和章节阅读；
- 当前 Revision 的全本/范围 TXT 导出；
- 明确的导出结果、跳过章节和覆盖错误。

### 导入与编辑

- 从大纲文件创建；
- 外部 TXT/Markdown 分阶段导入及恢复；
- 用户编辑章节的友好投影与 Revision 冲突处理；
- EPUB 3 导出。

### 发布与运维

- 作品归档、备份、恢复和跨设备迁移；
- 封面、作者、简介等发布元数据；
- 在不改变核心 Authority 的前提下接入发布平台适配器。

## 7. 验收标准

1. 用户能从作品库找到并继续任一本书，不依赖当前工作目录；
2. 导入失败或进程退出不会污染正式 Project，重启后只补做缺失阶段；
3. 外部编辑过期时明确冲突，不静默覆盖新 Revision；
4. TXT/EPUB 不泄露内部创作数据，章节顺序和标题稳定；
5. 导出可以在创作运行中执行，且不改变 Authority 或 CreationRun。
