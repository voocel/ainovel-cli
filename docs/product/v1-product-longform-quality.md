# v1 产品方向：长篇质量与上下文

> 状态：Planned Product Direction
>
> 约束：遵循 [`../v1-architecture-plan.md`](../v1-architecture-plan.md) 的 Authority、Derived、Review Outcome 和 Context Builder 边界。

## 1. 产品目标

让作品写到几十章、数百章后，模型仍能获得完成当前任务所必需的故事记忆，同时让用户知道系统记住了什么、遗漏了什么、为什么引用这些内容。

重点不是把更多文字塞进上下文，而是用可追踪、可失效、可重建的数据提高跨章连续性和审阅质量。

## 2. 从 v0 保留什么

保留用户价值：卷/弧/章分层摘要、角色状态、伏笔台账、相关章节推荐、下一章衔接、阶段审阅和上下文健康度。

不迁移 v0 文件工件作为第二事实源，也不迁移固定阈值、静默截断或由 Prompt 自行猜测状态的做法。所有记忆都必须绑定 Project Revision，并能从 Authority 重建。

## 3. 长篇记忆产品

Derived 层逐步提供：

- 章节摘要：事件、状态变化、关系变化、伏笔动作和章末衔接；
- 弧摘要：阶段冲突、角色路线、未解决问题和审阅结论；
- 卷摘要：结构进展、长期承诺、世界变化和下一卷入口；
- 角色状态：当前位置、目标、能力、关系、已知信息和最近出场；
- 伏笔索引：埋设、推进、回收、放弃及来源章节；
- 事实与章节关联：角色、地点、物品、事件和关系的引用图；
- 轻量正文索引：允许 Writer/Editor 按需回读原文，而不是把全书正文塞入 Prompt。

这些数据只帮助检索和审阅，不能覆盖 Intent、Plan、Canon 或 Manuscript。

## 4. Context Builder

每次 Operation 使用显式模型上下文预算，并先满足核心最低契约，再按任务相关性装配材料：

```text
硬约束与当前任务
→ 当前 Plan 路径与最新 Canon
→ 上一章结尾和近期摘要
→ 相关角色/地点/物品/伏笔
→ 高相关历史章节或摘要
```

来源、Revision、选择理由和占用量必须可查看。预算不足以满足最低契约时明确失败或等待用户调整，不静默丢弃 locked/guided 约束，也不伪装成完整上下文。

## 5. 质量审阅

阶段审阅和终审继续产出 Review Artifact 与 Verdict。产品默认提供设定一致性、角色行为、节奏、叙事连贯、伏笔、钩子和语言品质等维度，但具体 Rubric 可以由 Pack/Profile 扩展，不写死进 Coordinator。

审阅必须引用章节与具体发现；用户可以接受建议、局部重写、调整后续计划或忽略非阻塞建议。只有阻塞发现影响完成契约，普通审美建议不能制造无限重写循环。

## 6. 实施顺序

1. 先记录上下文来源、大小、缓存命中和审阅结果，建立真实基线；
2. 增加章节摘要、角色状态和伏笔索引；
3. 增加弧/卷摘要与相关章节检索；
4. 把 Context Builder 从全量 Plan/Canon 收敛为任务相关集合；
5. 用 v1 自产作品对连续性、召回率、成本和文学效果做对照实证。

不先建设向量数据库或通用知识图谱；只有确定性索引和结构引用不足时，再以真实数据决定检索技术。

## 7. 验收标准

1. 作品增长时，单次写章上下文保持在显式预算内，而不是随总章数线性增长；
2. 修改正文或 Canon 后，相关 Derived 数据按 Revision 失效并可重建；
3. 人为注入角色状态、伏笔和时间线冲突时，审阅能给出带来源的发现；
4. Context Builder 可以解释每份材料为何进入本次任务；
5. 至少用一部真实模型长篇证明连续性优于全量堆叠或简单滑窗。
