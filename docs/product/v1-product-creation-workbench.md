# v1 产品方向：创作工作台

> 状态：Planned Product Direction
>
> 约束：遵循 [`../v1-architecture-plan.md`](../v1-architecture-plan.md)，本文件只设计用户体验和应用用例，不定义新的创作内核。

## 1. 产品目标

让用户始终停留在“同一本书、同一条创作进度”中，通过调整自动化程度完成从一句话创作到逐章精修的连续体验。

```text
创建作品 → 持续创作 → 查看/修改/审阅 → 继续推进 → 完成作品
```

用户可以随时介入，但不需要理解 CreationRun、Operation、Proposal 或 ChangeSet 等内部术语。

## 2. 从 v0 保留什么

保留用户价值：一句话开始、共创式需求整理、实时进度、自然语言干预、逐章验收、暂停恢复和 Headless 入口。

不迁移 v0 的 `Phase / Flow / Steer` 并行状态和模式专用分支。v1 中所有动作都映射为现有 Project 修改、CreationRun 控制、Operation 执行或审批决定。

## 3. 入口契约

外层启动只区分交互形态，不承载产品功能分发：

```text
ainovel-cli                         # 人类主入口：进入 TUI
ainovel-cli --headless <动作> ...   # 无交互执行，供脚本、CI 和外部集成使用
ainovel-cli --help | --version      # 程序级信息
```

- 普通用户在 TUI 内完成创建、切换、创作和管理，不通过功能子命令切换界面；
- Headless 是同一组应用 用例的非交互入口，不建立简化流程；
- Project 通过作品库选择，不把当前工作目录当作一本书的身份。

## 4. 页面流转与首页

TUI 只有“首页”和“作品工作台”两级主导航。配置、导入和资产管理可以使用向导或面板，但不形成新的创作模式。启动按用户状态确定落点：

```text
启动
 ├─ 未配置模型 → 配置向导（选择 Provider、验证连通）→ 首页（欢迎页）
 └─ 配置完成   → 首页（欢迎页）；上次打开的作品在作品库中预选，
                回车即回到该作品工作台并恢复落点
```

启动不直接跳进任何作品：欢迎页始终是配置完成后的落点，"恢复"是欢迎页上
一次回车的距离，而不是一个绕过欢迎页的分支。

首页以一句话输入为主体：输入创作要求，回车即创建作品并进入工作台。其他入口只有完善创作设定、使用大纲或导入小说、打开作品库和进入配置。自动化程度与目标章数是创建选项，不是入口模式。

一句话、完善设定和已有材料只产生不同的初始化输入，最终创建相同的 Project 与 CreationRun。预设只初始化控制旋钮（§6），进入工作台后随时可调，不产生第二套页面或运行状态机。

键位遵循三条原则：输入框常驻聚焦，文字即要求或修改意见，动作一律走 `/` 命令，没有单键快捷操作；Esc 语义分层（清空输入、关闭全屏、回到跟随、返回首页）；鼠标只做滚轮与点击章节/标签/决定卡/底栏动作（开启鼠标捕获换取滚轮/点击，终端划选复制需按住 Shift，取舍详见工作台页面设计 §4）。终端最小 120 列 × 36 行，更小只提示最大化窗口；180 列以上右侧多一栏「本轮运行」实时数据（模型、代理、用量）。

### 创作首页布局（2026-09-11）

首页采用与工作台一致的终端原生背景、低饱和强调色、细分隔线和固定底栏：

- 顶部为品牌与模型设置；主要区域为故事输入、目标章数、自动化程度、更多设定和开始创作。开始按钮固定在右侧。
- 作品库显示标题、固定宽度进度和运行状态，按最近运行更新时间排序；仅渲染视口内条目。空作品库引导输入新故事。
- `/`（作品库焦点下）或点击搜索筛选标题与 ID；输入故事时 `/` 保留为正文输入。`PgUp/PgDn` 翻页，`Home/End` 定位首尾，点击作品直接打开。
- 目标章数可点击或按 Enter 直接输入；搜索、章数编辑期间保留输入焦点，Enter 确认、Esc 取消。Tab / Shift+Tab 遍历控件。
- 作品摘要查询仅读取 Intent、当前有效章节数与最近运行信息，列表不加载章节正文。进度条宽度不随目标章数变化。
- 更多设定、导入、模型配置沿用统一页面外框，反馈与快捷键固定在底部；原有连通验证、显式删除确认和审批流程保持原契约。

## 5. 核心体验

工作台由五个稳定视图组成：

- 作品总览：目标、当前 Revision、章节进度、运行状态和下一步；
- 正文：按卷/章阅读和编辑，显示修改是否已提交；
- 蓝图与事实：查看 Plan、Canon、Intent 和用户锁定范围；
- 审阅与决定：集中处理审阅发现、影响报告、批准、拒绝和重写；
- 活动与诊断：用创作语言展示正在做什么、为何等待以及如何恢复。

工作台常驻状态栏：书名、章节进度、运行状态与下一步。出现待决定事项时以决定卡置顶呈现“发生了什么、你的选项是什么”（批准、拒绝并说明理由、调整预算、修改后继续），用创作语言而非协议术语；决定卡是工作台的第一交互，不是埋在某个视图里的列表。

工作台页面的布局、实时活动流与流式数据管道设计见 [`v1-product-workbench-page.md`](v1-product-workbench-page.md)。

一句话入口只隐藏复杂度，不删除这些能力；用户随时可以展开工作台进入精细控制。

## 6. 控制连续体

产品不提供互相隔离的“快速模式/共创模式/导演模式”。入口预设只初始化 Approval、Ownership 和 RunStrategy，此后用户调整的是同一组控制旋钮：

- 自动推进：持续运行到目标或必须确认的位置；
- 里程碑确认：卷、弧或重大影响时等待；
- 逐章确认：每个新章节完成后等待用户；
- 局部锁定：只锁定结局、角色底线、某个节点或正文；
- 自动修订预算：限制系统可自行重写的次数。

控制收紧、放松和配置生效时间完全遵循核心架构，不在 UI 中发明额外语义。

## 7. 用户干预

用户输入分为三类：

1. 确定性运行控制，例如暂停、继续、取消、调整目标和修订预算；
2. 明确文档编辑，例如直接修改某章、Plan 节点或 Project Overlay；
3. 自然语言创作要求，例如“把感情线提前”或“第三章节奏太慢”。

前两类直接调用对应应用用例。第三类落为 Directive（核心 §4.9）：保留用户原话、带作用域入账，由 Context Builder 装配、审阅裁定核验；不翻译成事实变更，不写进隐藏状态，也不交给一次分诊猜动作。若一句输入实质上是事实变更（“第 10 章 A 其实已经知道秘密”），界面引导走 Proposal 与影响分析；两者可以共用一个输入框，但必须是两个对象。拒绝理由是作用域为该章的 Directive，必须回到后继重写任务，不能只作为聊天记录存在。工作台底栏的输入框常驻聚焦：纯文本回车即要求，在审阅视图中即修改意见；输入开始时固定作用范围与对象。第一类运行控制走 `/` 命令，批准须在审阅上下文中输入 `y` 回车。

## 8. 能力层次

### 基础闭环

- 落地入口契约、配置向导与首页；
- 打通一句话、完善设定和已有材料三个创建入口；
- 提供作品总览、章节阅读和当前运行进度；
- 补齐 CreationRun 暂停、继续、取消、目标/策略调整和统一续跑；
- 提供等待事项列表及批准、拒绝、查看原始诊断；
- Headless 与 TUI 调用同一组应用 行为。

### 精细控制

- 正文、Plan、Canon 和 Ownership 的可视化编辑；
- 自然语言要求落为 Directive，可查看命中范围与核验结果；事实类修改转为可检查的 Proposal；
- 逐章验收和里程碑确认的快捷体验；
- Revision Diff、影响范围和回滚入口。

### 完整工作台

- 完整多面板 TUI，并为 Web/桌面入口复用同一查询模型；
- 实时流式活动、审阅对照和批量修改体验；
- 可保存的工作台布局与用户偏好。

## 9. 验收标准

1. 不带参数只进入 TUI；非交互动作必须显式进入 Headless；
2. 用户可以从首页创建或打开任一本作品，不依赖切换当前工作目录；
3. 同一 Project 可以从无人干预创作切到逐章确认，再切回自动推进，不创建第二套运行历史；
4. 用户修改方向后，受影响范围、待决定事项和继续位置都清晰可见；
5. 等待、失败和恢复不要求用户输入内部 ID，TUI 与 Headless 对同一动作产生相同 Service 结果；
6. 入口层不直接访问 Store，也不包含文学路由判断。
